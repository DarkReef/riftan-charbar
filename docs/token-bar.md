# Панель и запросы проверок

Ручка ⠿ перемещает панель; положение сохраняется в клиентской настройке. Можно использовать стрелки клавиатуры с шагом 10 пикселей. При повторном отображении координаты ограничиваются размером экрана.

Результат запроса отображается в строке персонажа как «1 степень провала». Наведение показывает бросок/цель, исходный и применённый ситуационный модификатор, сложность и итоговый модификатор. Стандартный расчёт степеней системы сохранён. Отдельное дублирующее сообщение больше не создаётся: штатное сообщение броска хранится как источник результата и скрывается в ленте, когда доступна родительская карточка запроса. Если запрос удалён, штатная карточка снова доступна. Режимы видимости броска сохраняются.

Встроенные результаты требуют API системы с supportsRollMessageFlags. До обновления системы кнопка не выполняет бросок и сообщает о необходимости обновления. Проверка реального обновления DOM чата, сохранения позиции и нескольких клиентов Foundry ещё требуется.

Компактная панель внизу сцены показывает доступных персонажей и открывает их листы. Её можно отключить в клиентской настройке «Компактная панель персонажей». Мастеру доступны «Запрос целям» (помеченные цели) и «Запрос выделенным» (выделенные токены). Повторяющиеся связанные Actor получают один запрос; независимые Actor токенов остаются отдельными получателями.

Мастер задаёт характеристику или умение, сложность числовым бонусом/штрафом, отдельный ситуационный модификатор и пояснение. Владелец запускает проверку из чата через окно с предзаполненными параметрами, может изменить сложность и модификатор или отменить. Значения мастера и игрока сохраняются в результате. Проверка должна присутствовать у каждого получателя; специализации умений в этом списке пока не представлены.

Карточки оружия смещены на 64 пикселя ниже панели токена. Живая проверка расположения при разных масштабах сцены и многопользовательского запроса пока не выполнена. Защита от повторного нажатия действует внутри клиента; одновременные ответы с двух клиентов одного владельца требуют отдельной серверной координации.
